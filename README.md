# dataroom/fence — 数据室围栏全文检索库

纯内存、零依赖的 Go 库：装载单个数据室的语料与目录树后，按每位用户
真正可见的文档集合计算全文检索结果。上层完成身份核验与 NDA 确认后，
直接以串行方式调用三个操作：

- `Load(folders, docs)`：一次性装载房间语料（正文为已抽取的当前版本，
  每份文档有唯一整数 ID 且只属于一个文件夹；目录树最多 10 层，装载后不可变）。
- `ReplaceGrants(userID, folderIDs)`：替换某用户的全部授权。授权一个文件夹
  即可见其及全部子孙目录中的文档；多个授权取并集，祖孙重叠不重复计数；
  空授权看不到任何文档。下一次搜索立即生效，且不影响其他用户。
- `Search(userID, query)`：返回命中总数及得分最高的 20 份文档
  （得分降序，同分按文档 ID 升序）。

## 检索规则

- 连续英文字母为词，忽略大小写，其余字符均为分隔符；查询含 1–4 个
  不同的词，重复词只算一次；包含全部查询词的可见文档才算命中。
- 查询词权重 = 可见文档总数 − 含该词的可见文档数 + 1；文档得分为各
  查询词在该文档中的出现次数乘对应权重之和。统计范围是该用户的全部
  可见文档，增减不可见文档不会改变命中总数、得分或排名。

## 实现要点

- 装载期为每份文档建立排序词表（词 ID + 词频），并为每个词建立倒排表；
  同时为每个文件夹预计算子树文档列表（深度 ≤10，总量有界）。
- 授权替换时把各授权文件夹的子树文档并入位图，得到该用户的可见集合
  （缓存至下次替换）。
- 搜索时按代价二选一：倒排表较短则扫描倒排并按位图过滤；可见集合较
  小则遍历可见文档并在其排序词表中二分查找。两类极端负载因此都快。

## 运行测试

```sh
go test ./...          # 全部正确性 + 规模负载测试
go test ./fence/ -run TestScale -v   # 仅规模负载与内存测试（含耗时日志）
go test ./fence/ -run Example -v     # 可运行示例
```

规模测试：20 万文档 / 2 万文件夹 / 2000 用户 / 2 万词表，两类负载各
连续 1000 次「替换授权 + 搜索」（授权组合与查询词均变化），断言各自
合计耗时 ≤5 秒，并断言堆内存占用 ≤512 MiB。本机参考结果：负载 A 约
6 ms，负载 B 约 1.1 s，堆占用约 131 MiB。

正确性测试用一个与库完全独立的参考实现（直接对每个用户的可见正文
重新分词、统计、打分、排序），逐项比对命中总数、得分与前 20 名，
覆盖：祖孙授权重叠后撤去其中一项、两个用户搜索相同词、向不可见分支
加入大量高词频文档、空授权、未知词、重复查询词、分隔符与大小写、
装载结构校验（重复 ID、未知父目录、深度超限）以及随机语料对照。
